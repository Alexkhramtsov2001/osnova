# OSNOVA PLAN — действующая документация и архив v2.1–v2.14

Этот каталог перенесён из предоставленного владельцем архива `OSNOVA_PLAN_TZ_v2_1-v2_14.zip` от 15.10.2026. Технические главы, справочные материалы и чек-листы скопированы без изменений. Исходные файлы `README.md` и `AGENTS.md` сохранены как [SOURCE_README.md](SOURCE_README.md) и [SOURCE_AGENTS.md](SOURCE_AGENTS.md), чтобы архивные правила не подменяли действующий `AGENTS.md` в корне репозитория.

**Начинать чтение со [спецификации v1 от 20.10.2026](V1_SPECIFICATION.md), затем [целевой концепции](PRODUCT_VISION.md), [модели CAD-редактора](CAD_ARCHITECTURE.md) и [плана расширения](RELEASE_PLAN.md).** Сначала OSNOVA PLAN разрабатывается отдельно, затем подключается к сайту и его калькулятору. Долгосрочная цель — многофункциональный браузерный CAD без ИИ и серверной обработки. Архивные исключения DXF, 3D, сложных контуров, фасадов и разрезов ограничивают первый выпуск, а не дальнейшее развитие. Рабочие строительные чертежи — отдельная поздняя цель с собственной спецификацией и инженерной проверкой.

**Для выполнения конкретной кодовой задачи использовать [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md):** 68 небольших задач v1 с зависимостями и проверяемыми результатами, дальнейшая последовательность 2D CAD/3D/видов и правила продолжения между сессиями. Один запрос выполняет одну задачу, не весь выпуск. B01 выполнен локально в соседнем osnova-plan; там же PROGRESS.md с результатами. Следующая — B02, только по отдельному поручению. По указанию владельца новый код и проверки остаются на ПК до почти полной готовности v1 и в репозиторий сайта не добавляются; remote/push не настроены. Перечень этапов не является поручением их начинать.

Для правил и приёмки первого выпуска действует `V1_SPECIFICATION.md`; для долгосрочной цели — `PRODUCT_VISION.md`; архив используется в непротиворечащей части. В v1 линейный допуск — до 50 мм, площадь комнаты — ±max(2%, 0,25 м²). Архивные ±0,005 м², полная компенсация L1–L4 и статус `infeasible` не являются требованиями v1. Прежние чек-листы читать с этими заменами, а действующие критерии брать из раздела 11 спецификации. Решённые вопросы и технические проверки перед этапами перечислены в `references/OPEN_DECISIONS.md`. Наличие документации не означает готовности функций или прохождения приёмки.
