# OSNOVA PLAN — этапы и расширение функций

Статус: план возможностей, не график сроков и не поручение писать код. Применяется вместе со [спецификацией v1 от 20.10.2026](V1_SPECIFICATION.md) и [целевой концепцией](PRODUCT_VISION.md). Исходная дорожная карта `docs/13_ROADMAP.md` сохраняется как архив; при расхождении действует v1. Этапы B–D выполняются в отдельном приложении, E — интеграция первой публичной версии с сайтом. Расширенные свободные CAD-команды начинаются на этапе F.

Этапы делятся на небольшие независимые задачи с отдельным поручением владельца. В v1 входят только правила новой спецификации; полная компенсация L3/L4, более точные допуски, дополнительные крыши и каталоги остаются расширениями. Этапы F–H не выдаются за уже реализованные функции. Реализация остаётся локальной для пользовательских данных. Бесплатный статический хостинг, память/производительность устройства и поддержка браузеров проверяются на соответствующих этапах; тяжёлые модули загружаются по необходимости.

Подробная последовательность — [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md): B01–B12 (12 задач основы), C01–C31 (31 задача генератора/редактора), D01–D18 (18 задач надёжного приложения и экспорта), E01–E07 (7 задач интеграции). Всего 68 карточек v1; сложная карточка дополнительно делится до правок, а не выполняется вместе со следующим этапом. Там же описаны F01–F15, G01–G07 и H01–H03: путь к сильному локальному CAD и границы исследовательских/профессиональных функций. Подробные будущие контракты уточняются перед соответствующим выпуском, без обещания полного эквивалента AutoCAD.

B01 выполнен локально в отдельном соседнем osnova-plan: каркас, конфигурации и 3 Chromium smoke-проверки, без модели/геометрии. Новый код и проверки остаются только на ПК до почти полной готовности v1, remote и отправка не настроены. Изоляция предотвращает попадание ранних исходников в общие обходы ESLint/Vitest сайта. Следующая задача — B02 после отдельного поручения; этап E позже решает упаковку/подключение к сайту. Прохождение B01 не является доказанной готовностью алгоритмов B–H.

Для каждой задачи заранее фиксировать сценарий, типы данных, операции/ошибки, критерий завершения и соразмерную проверку. Для OSS фиксировать точную версию/коммит, лицензию и фактически пройденные проверки, отдельно от непроверенной совместимости с OSNOVA. Коммит, push и публикация — только по прямому указанию пользователя согласно корневому `AGENTS.md`. Текущая документационная задача не запускает реализацию, тесты сайта или публикацию.
