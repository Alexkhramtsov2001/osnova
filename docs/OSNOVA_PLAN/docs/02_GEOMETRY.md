# v2.2 + v2.13-A — Геометрия

> **Архив от 15.10.2026, не действующее ТЗ или инструкция.** Для v1 применяются [V1_SPECIFICATION.md](../V1_SPECIFICATION.md), для порядка работы — [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md). При расхождении они имеют приоритет над текстом ниже. Старые допуски, статусы поиска, объём редактора, маршруты и проверки не переносить в реализацию без сверки; приёмка v1 — раздел 11 спецификации. Исходный текст сохранён для истории.

**Система координат:** начало сверху слева, X вправо, Y вниз. Внешние размеры — по наружным поверхностям фасадов. Центральные линии стен и толщины — целые миллиметры; стены только горизонтальные/вертикальные. Чтобы сохранить полумиллиметры на поверхностях стен, вычислительное ядро использует удвоенные координаты `q=2*xMm`; при оси x=4000 мм и толщине 125 мм поверхности на 3937,5 и 4062,5 мм (`q=7875` и `8125`).

**Площадь:** хранить точную вычисленную площадь в четвертях мм²: `areaQ4 = 4 * areaMm2`, `areaM2 = areaQ4 / 4_000_000`. Допуск 0,005 м² = 20 000 единиц areaQ4. Для ортогонального полигона площадь вычисляется формулой Гаусса на удвоенных координатах: `abs(sum(x_i*y_(i+1)-x_(i+1)*y_i))/2`. Не округлять перед валидацией. При потенциальном выходе за пределы точных integer JS применять безопасную целочисленную арифметику / BigInt с явной сериализацией.

**Стены:** одна сущность на общую перегородку; центральная линия, толщина, материал, классификация, locked. Материальные следы объединяются геометрическим union, L/T/X-стыки не учитываются дважды. Наружные габариты должны совпадать с заданным прямоугольником. Нормализация удаляет дубли/нулевые рёбра, но не двигает стены молча. Разные материалы в стыке требуют детерминированного правила приоритета.

**Комнаты:** каноническая стеновая сеть и границы свободных областей — источник истины. Чистые полигоны комнат производны; не хранить независимые редактируемые полигоны, противоречащие стенам. Сгенерированные комнаты прямоугольные, объединённые вручную — простые ортогональные, без дырок. Не допускаются самопересечения и пересечения внутренностей комнат. Семантические ID сохраняются при обычной реполигонализации, при физическом объединении создаётся новый ID с сохранением требований.

**Баланс этажа:** `gross = unionWalls + netPhysicalRooms + unallocated + truePlanVoids`, классы взаимно непересекающиеся. Функциональные зоны не прибавляются второй раз. Лестничный след нижнего этажа — часть циркуляции, отверстие в плите верхнего — отдельная конструктивная величина, не двойное вычитание.

**Графы:** геометрическое соседство только при общей границе положительной длины; граф доступности строится по реальным дверям/проходам и лестнице. Каждое обязательное помещение достижимо от входа. Проёмы закреплены на wallId с offset/width; должны помещаться в стене и соблюдать ограничения.

**Тесты:** 4000×4000 мм = 16 м²; допуск +0,005 проходит, +0,006 нет; две полосы 1000×100 мм с пересечением 100×100 мм дают union 190000 мм²; точечное касание не соседство; нулевые/диагональные стены отклоняются; лестничный void не вычитается дважды; экспорт/импорт сохраняет координаты.
