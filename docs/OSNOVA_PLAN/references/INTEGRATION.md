# OSNOVA PLAN — интеграция с калькулятором и сайтом

Обновлено 20.10.2026. Требования, а не готовая интеграция. Численные правила и приёмка — в [спецификации v1](../V1_SPECIFICATION.md).

## Сначала отдельное приложение

Ядро генератора, модель, валидатор и формат не импортируют React Router, авторизацию, Supabase, оплату, кабинет или хранилище смет сайта. Отдельная оболочка использует их через публичные команды и адаптеры; в OSNOVA они подключаются на этапе E. Точный путь будущего пакета выбирается при начале этапа B, не создаётся документационной задачей.

Веб-стек сайта — React/TypeScript/Vite; при интеграции сохранить GitHub Pages base `/osnova/`. Маршруты PLAN из архивной UX-главы — будущие, не уже существующие адреса сайта. Отдельная версия не требует заранее менять App.tsx, конфигурацию или CI.

## Общие ограничения

Источники текущего поведения:

- `src/features/estimate/catalog.ts`: HOUSE_NUMBER_LIMITS, справочники и версии демонстрационных цен.
- `src/features/estimate/constraints.ts`: minimumArea, minimum/maximumPerimeter, minimum/maximumBedrooms, minimum/maximumBathrooms, fitsRoomLayout, нормализация.
- `src/features/estimate/types.ts`: HouseParameters и состав настроек.
- `src/features/estimate/calculations.ts`, `stageDefinitions.ts`: валидация, единицы/составы этапов, текущие коэффициенты и эвристики; это не готовое геометрическое ядро.

Будущий общий чистый модуль/адаптер ограничений должен обслуживать обе оболочки и иметь limitsVersion. При извлечении сохранить поведение калькулятора и связанные тесты, не переписывать его формулы. В v1 площадь 30–1000 м², от 60 м² для двух этажей; прочие зависимые границы берутся из общей модели. Проверки геометрической вместимости PLAN дополняют эти границы, не заменяют их молчаливым clamp.

Снимок параметров сохраняет версию правил и происхождение. Периметр и площадь задают прямоугольник по разделу 2 спецификации. Площадь калькулятора не равна сумме чистых комнат. Количество спален не означает известные площади и расположение: это отдельные требования мастера.

## Передача состояния

1. Каталог/калькулятор создаёт явный запрос к PLAN с известными параметрами и sourceProjectId/sourceEstimateId при наличии. Не передавать в URL весь чертёж или личные данные.
2. Мастер показывает вход, недостающие поля и изменения нормализации до генерации. Существующий план нельзя перезаписать новым входом при возврате по истории.
3. PLAN хранит собственный проект и ревизии. Исходная смета сайта остаётся отдельным документом; изменение PLAN не обновляет её автоматически.
4. Обратная передача фактических площади/периметра/этажности/настроек — отдельное действие с diff, проверкой округления и подтверждением. Не переносить чистую площадь комнат в area вместо наружной площади этажей.
5. Не переносить с PLAN учебную оплату, подтверждения или авторизацию. Подключение оформления не входит в v1.

## Каталог и количества

Цена/варианты этапов/коэффициенты могут быть общими. Геометрические количества рассчитываются отдельно: стыки, проёмы и stair void учитываются по фактическому проекту. Матрица itemId и условные позиции определены в разделе 8 спецификации. Ни старый getQuantity, ни синтетический HouseParameters не становятся доказательством геометрической точности.

Перед PDF проверять согласованность geometryRevision/pricingRevision/catalogVersion. Ошибка актуальной сметы не должна выдавать старую за новую. Изменение источника цен не переписывает исходные сохранения.

## Хранение и размещение

- PLAN использует отдельную IndexedDB `osnova-plan-db`, собственные версии и экспорт `.osnova`.
- Не менять ключ `osnova.saved-estimates.v1`, лимит и поведение существующих смет сайта, кабинет и черновики калькулятора ради хранения планов.
- Чертежи не отправляются в Supabase. Существующие демонстрационные функции сайта продолжают работать отдельно.
- Шрифт, Worker, JS и каталог располагаются локально; при интеграции все URL учитывают import.meta.env.BASE_URL. Существующий PDF-шрифт сайта — Noto Sans; нельзя полагаться на системный шрифт для кириллицы в экспорте.
- Проверить автономную статическую сборку и повторное открытие офлайн, затем `/osnova/`, прямые адреса и навигацию сайта. Наличие готового донора не доказывает эту совместимость.

До начала интеграции читать только относящиеся к ней файлы и текущее состояние Git; не проводить полный аудит сайта повторно. Проверки выполняются по реальному объёму изменений согласно корневому AGENTS.md.
