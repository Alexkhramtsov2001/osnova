## Проверенные ранее проекты

- [blueprint3d-modern](https://github.com/charmlinn/blueprint3d-modern), MIT: богатый референс стен и комнат, но приложение на Next.js/Three.js с собственной моделью. Перенос целого редактора в React/Vite/SVG усложнит соблюдение канонической геометрии; изучать отдельные алгоритмы/UX, не принимать как основу без PoC.
- [react-planner](https://github.com/cvdlab/react-planner), MIT: полезен как UX-референс; демонстрация использует старый React/Redux/Immutable, поэтому прямое встраивание в React 19 рискованно.
- [spox](https://github.com/benjaminwfriedman/spox), Python: пример постановки space-planning через ограничения, не готовый браузерный модуль. Лицензия репозитория не определена автоматически; не копировать код до проверки разрешения.

## Для поздних CAD-функций

- [Maker.js](https://github.com/Microsoft/maker.js), Apache-2.0: браузерная 2D-модель линий/дуг/слоёв и экспорт DXF/SVG/PDF; проверить типы архитектурных объектов, размеры, единицы, круговой обмен DXF и совместимость с текущей сборкой. Использовать как адаптер или источник идей, не делать вторым каноническим проектом.
- [JSCAD](https://github.com/jscad/OpenJSCAD.org), MIT для основного проекта с оговоркой об отдельных компонентах: параметрические 2D/3D формы; оценивать только на позднем этапе 3D и проверять лицензии конкретных пакетов.
- [three.js](https://github.com/mrdoob/three.js), MIT: кандидат для 3D-просмотра из той же канонической модели; сам не создаёт архитектурные проверки и не заменяет 2D-геометрию.

## Отложить или исключить из первой пробы

- [glpk.js](https://github.com/jvail/glpk.js), GPL-3.0: браузерный LP/MILP, но потребует отдельного решения о совместимости лицензии с проектом и всё равно не решит геометрию целиком.
- [or-tools-wasm](https://github.com/guwidoe/or-tools-wasm): обещает CP-SAT в браузере, но заявляет требование cross-origin isolation для потоков; это нужно отдельно проверить на текущем хостинге GitHub Pages до выбора.
- [Konva](https://github.com/konvajs/konva), MIT: зрелый Canvas-редактор, но ТЗ требует SVG и векторный PDF; смена основы рендеринга без решения владельца не предлагается.

## Практический порядок проверки без интеграции в продукт

1. На фиксированном наборе геометрических случаев из `docs/02_GEOMETRY.md` сравнить Clipper2-WASM и clipper-lib: union стен, L/T/X, наружные углы, отверстие плиты, сериализация целых удвоенных миллиметров. Независимый эталон — ручные аналитические площади; `polygon-clipping` использовать только как дополнительную проверку.
2. Проверить z3-solver на малой задаче прямоугольных комнат и ограничений площади, времени/отмены и работе Worker на GitHub Pages. Если стоимость слишком велика, оставить детерминированный backtracking из ТЗ.
3. Для хранения сравнить `idb` и Dexie на реальном CAS двух вкладок и ошибке записи. Выбрать одну библиотеку.
4. Для PWA и редактора тестировать только после фиксации продуктовых границ из `OPEN_DECISIONS.md`. Не переносить чужую модель здания как источник истины.

Критерии приёмки OSS из `docs/12_TESTING.md` остаются обязательными. Ни один кандидат пока не утверждён или установлен.
