# E — интеграция с OSNOVA только по поручению

Карточки документации v3.0. Общие правила, команды и критерий перехода — в [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md). Пути относятся к отдельному osnova-plan и являются планируемыми, если их ещё нет. Текущие статусы и границы выполненного — в [PROGRESS](../PROGRESS.md); будущие возможности не считаются реализованными по наличию карточки. Одна карточка/подзадача за запрос; будущие F/G/H сначала уточняются отдельным контрактом.

Согласованный целевой сценарий — [общее рабочее пространство](../INTEGRATION.md#3-калькулятор-и-plan-общее-рабочее-пространство): один текущий черновик, три представления, явный повторный поиск и отдельные сохранённые версии. Уточнение04.11.2026 — [UX-2026.11.04-1](../INTEGRATION.md#311-контракт-пользовательского-сценария-ux-20261104-1): известные поля автоматически заполняются без повторной анкеты/кнопки импорта, неизвестные сведения предлагаются явно, принятый план автоматически не заменяется. Первая передача снимка предшествует общей оболочке. E остаётся поздней интеграцией после S04; уточнения U07.1–U07.5 не внедряют сайт раньше E. Текущий статус — README/PROGRESS, старые C16.2 ниже не текущее поручение. Конкретный UI и код сайта сейчас не добавляются.

Уточнение FORM-2026.11.04-1 — [полный реестр/сценарий §3.12](../INTEGRATION.md#312-единая-анкета-стартовый-состав-и-недостающие-данные--form-20261104-1). E02 владеет13 полями HouseParameters/scope и совместимостью legacy A/P/bathrooms, версиями количеств/цены; новые санитарные функции не проходят под видом прежних одинаковых bathroom. E04.1 фиксирует provenance/default/proposal/derived/unknown и метаданные режимов, не второй источник геометрии. E04.2 создаёт видимое предложение состава один раз по известным counts/общей зоне/входу без второй анкеты; сохранённый состав приоритетен. E04.3 обслуживает counts↔список/auto/fixed атомарно без циклов и потерь ID. E04.4 даёт одну анкету и3 представления, E05 честную обратную представимость/покрытие сметы. Проверить2→3/уменьшение/удаление/смену источника, не воскрешать комнаты; выключенный этап сметы не отменяет функции дома. Раздельный санузел — только после принятого R-профиля, неизвестная инженерия не нулевая цена. Основной сайт не интегрируется этим уточнением.

## E04 — Передача сайта в PLAN и общий рабочий черновик

- **Цель:** Известные параметры переходят в PLAN без повторного ввода; затем три представления используют один рабочий контроллер.
- **Зависимости:** `E03`, `E04.6` (завершение).
- **Файлы:** Будущие input/provenance/workspace adapters и связанные unit/e2e; конкретный allowlist каждого подшага до кода.
- **Реализация:** По [INTEGRATION §3](../INTEGRATION.md#3-калькулятор-и-plan-общее-рабочее-пространство), последовательно .1–.6. Не переносить оплату/авторизацию и не дублировать формулы/канон здания.
- **Приёмка:** Известные параметры сохранены, все обязательные данные собраны в калькуляторе; один текущий черновик, устаревание плана видно, сохранённые сметы не переписаны. Back/history/новый источник не затирают более новый контекст.
- **Команды:** Адресные unit/contract/e2e изменённой области, TypeScript и точечный lint; без несвязанных страниц/полной регрессии после каждого подшага.

### E04.1 — Контракт данных, владельцы и идентичность

- **Зависимости:** `E03`.
- **Файлы:** INTEGRATION/ARCHITECTURE и будущие typed input/workspace DTO; сначала письменный контракт с примерами, затем узкие проверки транспорта.
- **Результат:** Зафиксировать ID рабочего контекста, PLAN Project/revision, nullable sourceProjectId/sourceEstimateId, origin snapshot, текущие параметры, geometry/pricing input revisions и версии. Таблица прав записи и переходов, provenance точного/приблизительного периметра и известных/предложенных/вычисленных данных, режим площади/размеров по принятому U07.2; одна каноническая геометрия, неизменяемый исходный снимок, существующие ID/схемы не переиспользуются в другом смысле.
- **Проверки/приёмка:** Два рабочих проекта и две версии сметы не смешиваются; устаревший внешний снимок не перезаписывает новый ввод. Нет необходимости сохранять смету/входить ради передачи; никаких чертежей/персональных данных в URL. Полный контракт Worker/CAS сохраняется, подпись UI не сертификат.

### E04.2 — Первичная передача снимка и недостающие поля

- **Зависимости:** `E04.1`.
- **Файлы:** Будущий адаптер calculator/catalog/manual и диагностика полей калькулятора; адресные contract/e2e.
- **Результат:** Адаптер переносит известные валидные поля и версии в общий черновик калькулятора один раз и возвращает список недостающего с привязкой к полям. Известный контур отличать от приблизительного старого P; предлагаемые габариты/цели подтверждаются в калькуляторе с указанием источника. Полный запуск определяет E04.6.
- **Проверки/приёмка:** Сохранённый/несохранённый расчёт, каталог, manual, отсутствующие цели; gross/net не смешаны, комнаты/периметр не выдуманы из фотографии/цены. Floors=2 до T не преобразуется в1. Новый источник поверх текущего проекта требует выбора применения/отдельного контекста. Старые defaults нового расчёта и «Продолжить» сохраняются.

### E04.3 — Один контроллер параметров и актуальность результата

- **Зависимости:** `E04.2`.
- **Файлы:** Будущий чистый workspace controller и input adapters; unit/contract tests до layout-кода.
- **Результат:** Общие желаемые параметры и ценовой черновик, одна нормализация, редактируемая строка отдельно от валидного ввода. Валидные изменения автоматически синхронизируются в одном контексте без повторного импорта. Geometry/pricing revisions и выбранный plan reference; сравнение актуальности, явный запуск/отмена без генерации на каждую цифру. normalizeForArea не удаляет комнаты/цели/связи незаметно; конфликт counts с настроенным списком требует согласования. Автозаполнение не автоматическое принятие нового плана/перезапись сохранений.
- **Проверки/приёмка:** Изменение площади/технологии помечает прежний план; регион/доставка/отделка обновляют цену без перестановки комнат и запуска Worker. Невалидное геометрическое редактирование не позволяет принять поздний ответ. Изменение числа комнат требует согласования пользовательских целей/связей; их скрытого удаления нет. Исходный estimate и Project не являются изменяемыми алиасами формы.

### E04.4 — Три представления и компактная панель

- **Зависимости:** `E04.3`.
- **Файлы:** Будущая оболочка/представления «Параметры / Планировка / Смета» и общие field components; адресные UI/e2e.
- **Результат:** Просторный чертёж и компактная сводка того же контроллера. Desktop допускает боковую сводку, mobile/tablet раскрывают её отдельно. Действие изменения входа возвращает в соответствующее поле калькулятора.
- **Проверки/приёмка:** На размерах SPEC §10 нет двух независимых форм, перекрытий и потери значений при переключении; клавиатура/focus/ошибки доступны. Видно, к каким параметрам относятся старый план и текущая цена. Новые UI-библиотеки/вторая React не нужны для этого контракта.

### E04.5 — Stale, история и сквозной вход

- **Зависимости:** `E04.4`.
- **Файлы:** Существующие маршруты/Worker client/контекст и адресные интеграционные tests.
- **Результат:** Проверить requestId/baseRevision плюс применимость геометрического ввода/контекста, смену проекта, повторный запуск, back/forward и передачу нового снимка.
- **Проверки/приёмка:** Поздний ответ старого проекта/ввода отклонён даже после неуспевшей отмены; ценовой черновик не инвалидирует совместимый геометрический ответ. Отмена/ошибка оставляет прежний принятый вариант. Старый URL не накатывает старые значения. Восстановление после refresh согласовано с D/E06; до успешной записи не обещать durable save. После .5 общий контекст и передача готовы; E04 закрывается только после .6.

### E04.6 — Калькулятор как единственный ввод, генерация без анкеты

- **Цель:** Пользователь заполняет все обязательные данные в калькуляторе, нажимает «Создать чертёж» и сразу попадает в генерацию. Отдельной анкеты PLAN нет; PLAN показывает только сводку переданного снимка и статус.
- **Зависимости:** `E04.5`.
- **Файлы:** Калькулятор сайта, typed handoff DTO, публичный PLAN-маршрут E03, сводка снимка; адресные unit/contract/e2e.
- **Результат:** Один калькуляторный ввод заменяет HouseStep/RoomsStep/PreferencesStep публичного пути. Кнопка активна только при полном валидном снимке; переход атомарный, один раз, без повторного ввода и без «недостающих полей» в PLAN.
- **Границы:** `plan.html` остаётся отдельным dev-стендом; U07.5 не сертифицирует публичный путь без анкеты. Отдельный импорт/вторая форма/скрытый ремонт состава запрещены.

#### E04.6a — Матрица обязательных данных и handoff-контракт

- Зафиксировать точный v2-контур и режим, подтверждённый источник, поддерживаемую этажность, технологию и чистую высоту, список помещений со стабильными ID, назначением и целями, режим входа. Связи используют ID из этого списка; пустой список допустим. A/P вычисляются из контура. Произвольные имена, пожелания и ценовые поля не требуются для запуска геометрии.
- Для каждого поля: владелец, provenance, версия, `required`/`derived`/`optional`, правило default и что делать при отсутствии.
- Handoff DTO версионирован и immutable. Ключ проверяется вместе с `contextId`, ревизией геометрического ввода, `baseRevision` и версиями профиля/правил. Данные снимка и личные данные не попадают в URL. Повторный клик во время обработки не создаёт второй запрос.
- **Проверка:** два разных расчёта не смешиваются; старый handoff не перезаписывает новый; неполный снимок не активирует кнопку.

#### E04.6b — Полный калькуляторный ввод

- Добавить в калькулятор недостающие поля и валидацию: точные габариты/площадь и сторону, высоту/технологию, состав, кухню, вход, цели, связи/пожелания.
- Auto/fixed целей и auto/custom имён — в калькуляторе; ручная цель не сбрасывается; старые цели без режима считаются fixed.
- Показывать одну сводку «что уйдёт в чертёж», без второй анкеты и без технических кодов в основном тексте.
- **Проверка:** 2→3/уменьшение/смена типа/кухни/входа не теряют ID и цели; невалидное поле не отправляется; все обязательные поля доступны на 390/375.
- **Демо-данные:** интеграционные сценарии переиспользуют состав из [Q01.1](Q_IPHONE.md#q011--подготовка-стендов-к-проверке-на-iphone) как тестовые данные. Каждый отдельный демо-стенд предзаполнен своим примером. Пустой реальный расчёт не получает демо-значений.

#### E04.6c — Атомарная передача и прямая генерация

- Кнопка «Создать чертёж» валидирует снимок, фиксирует revision и создаёт одну команду перехода и запуска Worker. При ошибке до запуска черновик сохраняется, причина видна в калькуляторе.
- PLAN показывает сводку, статус и отмену. После терминального исхода допустим отдельный явный повтор для того же актуального снимка с новым requestId. Изменение данных возвращает в калькулятор.
- Remount, reload и история не повторяют обработанную команду; восстановление черновика принадлежит E06. Новый кандидат требует явного принятия.
- **Проверка:** нет промежуточных House/Rooms/Preferences шагов; cancel/back/stale не запускают второй поиск; кнопка неактивна при неполном снимке.

#### E04.6d — Неполный снимок, legacy и dev-путь

- Неполный, неподдержанный или устаревший снимок возвращает в связанный калькулятор с текущим вводом и списком причин. Legacy A/P требуют явного подтверждения точного контура в калькуляторе. Старый сохранённый план доступен для просмотра по своему контракту.
- `plan.html` standalone остаётся для разработки/отладки и не считается публичным входом.
- **Проверка:** прямой URL без handoff не открывает генерацию; повреждённый handoff отклоняется; старый v1-план открывается без повторной анкеты.

#### E04.6e — Приёмка полного пути

- E2E: калькулятор → «Создать чертёж» → реальный Worker → просмотр/принятие → правка в калькуляторе → stale/повтор.
- Матрица: 8130², 66 м²/8×8,25, 180 м²/fixed side, rotation 0/90, legacy conversion, incomplete snapshot, mobile 1440/768/390/375.
- **Приёмка:** ни одного обязательного вопроса в PLAN; все данные совпадают со снимком калькулятора; оба демо-пресета (120/2WC и 80/1WC) проходят без ручного ввода; iPhone/WebKit отдельно; U07.5 и E07 не подменяются.
- **Стоп:** если хотя бы одно обязательное поле нельзя получить в калькуляторе, E04.6 не закрывается; возврат к E04.6a, не расширение анкеты.

## E05 — Обратная передача фактических параметров

- **Цель:** Осознанно применить параметры принятого плана к текущему расчёту, сохранив исходную смету.
- **Зависимости:** `E04`. Родитель закрывается после `E05.5`.
- **Файлы:** Будущие output/diff/apply adapters; адресные unit/contract/e2e.
- **Реализация:** По [INTEGRATION §3.7–3.8](../INTEGRATION.md), последовательно .1–.5. Быстрая оценка не выдаётся за геометрическую смету R.
- **Приёмка:** Gross/net/периметр/этажность и версии различаются; подтверждение/отмена и stale безопасны; исходный estimate не меняется от открытия/изменения PLAN.

### E05.1 — Diff текущего расчёта и плана

- **Зависимости:** `E04`.
- **Файлы:** Будущие projection/diff DTO и preview, сначала чистые unit/contract tests.
- **Результат:** Показать текущие и предлагаемые gross/perimeter/floors/settings, источник, ревизии и ограничения округления. Цели/фактические net площади комнат отдельно, неизвестное не становится нулём.
- **Проверки/приёмка:** Сравнение не мутирует стороны; отмена ничего не применяет; неподдержанные настройки объяснены. Модель из будущего другого профиля не сужается молча.

### E05.2 — Подтверждённое применение к рабочему черновику

- **Зависимости:** `E05.1`.
- **Файлы:** Будущая Controller command/общий calculator adapter; unit/contract и адресный e2e.
- **Результат:** По явному подтверждению проверить ревизии/ввод, применить параметры к общему черновику и пересчитать предварительную стоимость прежней функцией. Соответствующий новый снимок геометрии проверяется отдельно; старый proof не переносится на изменённый raw.
- **Проверки/приёмка:** Новая ревизия между preview и confirm делает diff устаревшим. Сохранённая смета/подтверждение оплаты не переписаны, цены/скидки не применены дважды; несовместимые настройки не теряются. Изменения видны во всех трёх представлениях.

### E05.3 — Ошибки и сохранённые версии

- **Файлы:** Будущие связи с существующим сохранением расчётов и output adapters; адресные отказные unit/e2e.
- **Результат:** Явное сохранение новой/обновлённой сметы, исходные ID/версии и честный статус ошибки. Контракт повторов/частичной записи согласовать с E06 до кода хранения.
- **Проверки/приёмка:** Ошибка актуального сохранения не открывает оформление старой сметы; данные прежнего estimate/Project доступны. Совместный PDF требует согласованного снимка; самостоятельный калькулятор работает без плана. Смена расчёта/оплата/учебная авторизация сохраняют существующую логику. После .3 обратный ввод и сохранение готовы; E05 закрывается после .5.

### E05.4 — Живая правка чертежа и автоматический пересчёт черновика (CALC-EDIT-2026.11.12-2)

- **Зависимости:** `E05.3` и соответствующая операция редактора R с валидируемой committed-ревизией, начиная с истории R03 и конкретной поддерживаемой команды R04+. E05.4 подключает такую ревизию к расчёту.
- **Файлы:** Будущие plan-revision/projection, calculator live adapter, панель под чертежом и адресные unit/contract/e2e.
- **Результат:** После завершённой правки автоматически обновляются фактические комнаты, контур, A/P и текущая предварительная цена. Сохранённая смета, принятый план и новая генерация остаются явными действиями.
- **Границы:** Живой пересчёт не запускает Worker, не переписывает сохранённую смету, не заменяет принятый план и не переносит старый score/proof на изменённый raw.

#### E05.4a — Единица правки и ревизии

- Одна валидная завершённая команда, меняющая геометрию, создаёт одну `geometryRevision`. Preview, повтор той же команды и no-op ревизию не создают. Цели и ценовые настройки меняют свои ревизии.
- Несколько полей одной операции применяются атомарно. Отмена preview сохраняет прежний снимок; undo/redo используют новую ревизию для восстановленных значений.
- Ревизии: `geometryRevision`, `priceRevision`, `savedEstimateRevision`, `acceptedPlanRevision`; открытый diff/панель привязаны к `contextId`, `planId`, `baseRevision`, `inputRevision`, `geometryRevision`, версии профиля.
- **Проверка:** drag 100 шагов → 1 committed revision; отмена не меняет ни план, ни цену; повторное применение не создаёт дубль.

#### E05.4b — Автоматический пересчёт текущего черновика

- После валидной правки обновить `derivedFromGeometry`: A/P, этажность, размеры, фактические площади комнат.
- Один раз вызвать существующую функцию предварительной цены; не суммировать дельты, не округлять повторно, не запускать Worker.
- Не трогать `userPricingInput`: регион, доставка, отделка, скидки.
- Показывать «предварительно». `priceRevision` привязана к ревизиям геометрии и ценовых настроек и версии каталога; результат старого пересчёта не применяется.
- **Проверка:** изменение только региона пересчитывает цену без геометрии; изменение контура пересчитывает A/P и цену; ошибка цены не обнуляет комнаты.

#### E05.4c — Панель под чертежом: комнаты и кастомный вариант

- Показывать итог, дельту к предыдущей/сохранённой ревизии, контур, P, gross area.
- Список комнат: фактическая площадь/размеры, цель, режим `auto/fixed`, изменение.
- Бейдж «Кастомный вариант» и список отличий от исходного/принятого плана. Это статус происхождения, не отрицательная оценка.
- На mobile панель под холстом, сворачиваемая, без горизонтального скролла; итог и основное действие доступны без раскрытия деталей.
- **Проверка:** gross/net не смешаны; fixed-цель не переписана; комнаты и суммы не перекрываются на 390/375.

#### E05.4d — Stale, отмена и сохранение

- Правка помечает принятый план stale, но не заменяет его; новая генерация — только явное действие.
- Невалидная/неподдержанная правка сохраняет последнюю валидную цену с меткой её ревизии и показывает причину.
- Undo восстанавливает значения в новой ревизии с повторной проверкой. При ошибке расчёта прежняя цена помечена исторической; сохранить актуальную смету можно после успешного пересчёта.
- «Сохранить расчёт» — единственное действие, меняющее сохранённую смету; живой пересчёт её не переписывает.
- **Проверка:** back/forward/старый URL не накатывают старую цену; ошибка сохранения не открывает старую оплату; повторный вход не создаёт вторую смету.

#### E05.4e — Приёмка

- E2E: правка контура → авто-цена → stale принятого плана → явная новая генерация.
- E2E: внутренняя правка → комнаты обновились, gross/цена дома не изменились → новый plan revision.
- E2E: ручная цель → fixed; auto-цели не переписаны; отмена возвращает всё.
- Матрица: 66 м², 180 м²/fixed side, rotation 0/90, 8130², 390/375.
- **Стоп:** если редактор не выдаёт committed revision или цена не привязана к ревизии — E05.4 не закрывается; не подменять это пересчётом на каждое движение.

### E05.5 — Оценка кастомной ревизии (SCORE-REV-2026.11.12-1)

- **Зависимости:** `E05.4`, действующий score-контракт C15; отдельная методика не изобретается.
- **Файлы:** Будущие score projection/adapter, панель оценки и адресные unit/contract/e2e.
- **Результат:** Средний балл показывается только для валидной ревизии с полным покрытием критериев. Старый балл не переносится на изменённый чертёж.
- **Границы:** Балл не меняет цену, принятие плана и запуск поиска; «кастомный» не является минусом.

#### E05.5a — Контракт методики

- Применить `score-mvp-2026.10.26-1` из C15 с его шкалой и весами. E05.5 версионирует отображение и привязку к ревизии. Допустимо округлять показ, точную оценку сохранять для сравнения.
- Требовать полное покрытие применимых критериев. Только определённые в C15 исключения могут уменьшить набор; при отсутствующих измерениях показать «недостаточно данных».
- Балл привязан к `planRevision`, `geometryRevision`, `scoreRevision` и версии методики.
- **Проверка:** одинаковый вход → тот же балл; изменение весов/версии не переписывает старые оценки.

#### E05.5b — Живой или явный пересчёт

- Сборка оценки из полного проверенного набора фактов может обновляться после debounce. Дорогие измерения фиксированного плана выполняются только по «Перепроверить оценку», с отдельным бюджетом и отменой. Поиск альтернативных планов остаётся отдельным действием.
- Во время пересчёта показывать «оценка для ревизии N устарела», не старый балл как актуальный.
- Ошибка/таймаут оценки не блокируют сохранение и принятие; показывается честный статус.
- **Проверка:** правка → старый балл помечен; повторная оценка даёт `scoreRevision`; поздний ответ не заменяет новый.

#### E05.5c — Приёмка

- Панель: балл, ревизия, покрытие, статус, причина недоступности.
- E2E: оценка → правка → stale → перепроверка; неполное покрытие; ошибка оценки; мобильный вид.
- **Стоп:** нельзя показывать средний балл без полного покрытия или переносить его на другую ревизию.
