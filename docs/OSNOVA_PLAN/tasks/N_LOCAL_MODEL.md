# N — необязательная локальная модель

План согласован владельцем 26.10.2026 и заменяет прежний общий список из пяти исследовательских шагов в IMPLEMENTATION_PLAN §6. Это 19 новых опциональных карточек сверх исходных119; обязательная цепочка MVP47 не расширяется. Ни одна N-карточка пока не выполнена. Код/веса/данные не создаются наличием этого документа. Следующий текущий кодовый шаг C15.2 (арифметика, C15 ещё in_progress).

## Точки входа и развилки

| Часть                             | Карточки | Условие начала                                                                  | Результат                                                                          |
| --------------------------------- | -------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |

| Изолированные локальные пробы     | N05–N10  | Принятый D08/K3 и завершённый N04                                               | Сравнение без обучения, подтверждённый выбор либо отказ от ветви                   |
| Условное дообучение               | N11–N14  | N10 доказал недостаток готовой модели и обосновал обучение                      | Независимые данные, ограниченный опыт, сравнение адаптера с исходной моделью       |

C16 — проверка одноэтажного ядра; D08 — законченный MVP с U/D/Q; S04 — принятая автономная полная v1. Нельзя выдавать эти точки за одну готовность. В N01–N04 не скачивать веса, не устанавливать runtime и не запускать модель. Чтение характеристик ПК не является испытанием модели. Ожидание D08 или S04 не обходить исключением реального iPhone или иных критериев приёмки; независимые базовые задачи продолжаются.

Развилки после N10: **отложить** — N11–N19 не начинать, продолжить обычную дорожную карту; **использовать готовую модель** — N11–N14 пропустить и ждать S04 для N15; **проверить дообучение** — выполнить N11–N14 и принять отдельное решение. Неудачное обучение не обязывает внедрять его результат. N15 допустим с готовой моделью только при положительном N10; с обученным адаптером дополнительно обязателен успешный N14. Это явные условные связи, не обязательное включение обучения в каждый путь.

## Общие границы и формат работы

- Основной источник чисел/профилей — [SPECIFICATION](../SPECIFICATION.md), проверок — [ACCEPTANCE](../ACCEPTANCE.md), базовой архитектуры — [ARCHITECTURE](../ARCHITECTURE.md). K2/K3/K4 не ослабляются и не получают зависимость от N. Интеграция в основной сайт остаётся отдельным E.
- Одна карточка за задачу. Если карточка велика, до кода разделить её внутри того же ID с явными файлами/проверками; не выполнять всю ветвь одним запросом. После двух неулучшающих алгоритмических попыток — диагностика по согласованному процессу.
- Пути ниже планируемые в отдельном локальном osnova-plan. Они не означают, что каталог или интерфейс уже существует. N06 уточняет узкий протокол, N15 — окончательные файлы интеграции по фактической архитектуре S04. Не переносить исследовательские зависимости в основной package.json без доказанной необходимости.
- Документационные результаты N01–N06/N10/N11/N14/N15 фиксировать в этом документе и локальном PROGRESS; большие замеры, веса, датасеты, окружение и снимки хранить вне Git сайта. Код генератора остаётся локальным по действующим разрешениям. Новый remote/публикация/размещение весов не разрешаются этим планом.
- До первого сравнения закрепить критерии pass/fail и остановки: требования задачи, контрольные входы, число повторов, одинаковые бюджеты ядра, пределы времени/памяти/выхода модели. Числа задаются N01/N04 до замеров, не подгоняются после. Модель не меняет состав комнат/цели/источник, нормы, seed и допуски молча.
- Предложения модели — недоверенный ввод. Структурированный JSON проходит строгий разбор и смысловую проверку; геометрию/проёмы/маршруты проверяет прежний независимый валидатор. Ошибка модели не меняет принятый план. Отключённое расширение сохраняет прежний сценарий без загрузки весов.
