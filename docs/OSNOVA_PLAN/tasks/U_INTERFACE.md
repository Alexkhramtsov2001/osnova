Контракт .2a: `decodeWorkerCommand(unknown)` и `decodeWorkerReply<T>(unknown, isResult)` возвращают frozen `{ok:true,value}` либо `{ok:false,code}`; ошибки invalidData/limitExceeded/invalidEnvelope/invalidResult различаются. `copyTransportData` владеет detached immutable данными; разрешает конечные числа, string/boolean/null/BigInt, dense массивы и plain/null-prototype records, не вызывает getters/toJSON/итераторы. Циклы, функции, symbol keys, нестандартные прототипы и расширенные массивы отклоняются. Повторные ациклические ссылки копируются независимо, исходник не замораживается. Пределы одного пакета:100000значений/32уровня/1000000суммарных UTF-16 code units строк и ключей/1024hex-цифры BigInt. Это ресурсный предел транспорта, не изменение q/площадей или бюджетов поиска; превышение явно отклоняется.

Progress имеет ровно phase(string≤128|null), nodes/checkedCandidates/accessSteps (неотрицательные safe integers). Failed имеет только code=protocolError|cloneError|workerError. Finished требует обязательный type guard результата; codec не приводит unknown к GenerationResult и сам не доказывает геометрию или свежесть ревизий. На .2b guard внедряется зависимостью; при настоящем adapter U01.3 должен быть связан с конкретным доменным контрактом, до U01.4 — проверен actual MVP вне Worker. Пока этот binding отсутствует, toy payload unit-теста не считается результатом ядра. Контроль request reuse/stale/deadline/Worker-instance относится к .2b; .2a только сохраняет и проверяет структуру идентичности.

API .2b до реализации: `createWorkerClient<T>({createWorker, clock, isResult})`; clock предоставляет now/setTimeout/clearTimeout без синхронного вызова callback внутри setTimeout. `start(unknown)` принимает полный start-конверт .2a и возвращает Promise ровно одного host outcome: success с неизменённым по смыслу terminal T, failure с ограниченным кодом, cancelled или timeout. Host success означает успешную доставку, а не доменный статус success/принятие плана. `cancel(requestId)` действует только на текущую операцию, `invalidate()` немедленно отменяет её при любом геометрическом редактировании (включая невалидное) или смене контекста/основания, `dispose()` окончателен. `getState()` выдаёт immutable phase/identity/progress без записи Project, сохранений или принятого плана. Владелец будущего UI обязан вызвать invalidate до ожидания нового валидного ввода; сравнения входящего конверта с захваченной identity не заменяют этот вызов.

Первый client создаёт новый порт на каждую допустимую операцию и terminate на каждом её выходе, без очереди/пула и cooperative grace. Ошибки входного codec invalidData/limitExceeded дают cloneError, прочие ошибки схемы/guard — protocolError; reuse/disposed имеют отдельные host-коды, сбой clock/factory — workerError. Ресурсные ошибки не превращаются в доменные отказы. Проверка монотонного now выполняется до и после декодирования ответа; setup/copy/delivery входят во внешний срок. Для malformed raw.mode применяется защитный normal-дедлайн, сам raw без исправления передаётся прежнему ядру. Это не дополнительная формула или валидация профиля.

В .3a нет обращения к DOM/Worker globals и новый tsconfig не нужен. В .3b entry исключается из DOM-сборки и проверяется отдельным worker tsconfig без изменения core lib. Родитель U01.3 закрывается только после обоих; настоящий Chromium остаётся U01.4.

Первый scheduler фиксирован: максимум64 next или8мс на task, включая создание cursor; между порциями только будущая macrotask (в браузерном binding setTimeout0), не Promise-loop. Finished сохраняет terminal ядра, а сбои адаптера дают failed, не доменный invalidInput. Отказ протокола/dispose также освобождает cursor без публикации частичного результата. Повторный requestId запрещён, перекрывающиеся start — ошибка протокола, поздний cancel иной identity игнорируется.

Значения64/8/100 — первоначальные параметры доставки; влияют на накладные расходы в прежнем реальном deadline, не расширяют поиск. Сравнение качества/скорости под настоящим Worker и полного входа pending U01.4; не оптимизировать их вслепую по этим коротким пробам.

Контракт .3b: `generate.worker.ts` связывает .3a с performance.now/postMessage и событиями message/messageerror; terminal не переписывается. Первоначальная доставка setTimeout0 заменена в U01.4 на отдельные задачи MessageChannel после измерения браузерного clamp; max64next/8мс/100мс сохраняются. Очередь имеет один callback, token fencing отменённого сообщения и dispose обоих портов; это не цикл microtask. Host boundary — `GenerationResultTransport`: конкретные поля/версии/ledger/quality/selection terminal проверяются после owned-copy codec. Вложенные raw.layout и snapshot остаются readonly transport records, а не утверждением типа GeneratedGeometry/MvpGeometrySnapshot. Данные terminal не исправляются и не заменяются. До применения/показа геометрии обязателен прежний validateMvpGeometry(raw) вне Worker; сохранённый snapshot не является сертификатом. Изменение вложенной геометрии может пройти только транспортный формат, но не получает геометрической приёмки. Клонированная qualityEvaluation проверяется как структура отчёта, не восстанавливает private ownership для comparator. Это уточнение безопасной типизации границы, не второй алгоритм, новое строительное правило или сокращение проверки U01.4. Публичный decoder/factory не экспортирует сырой guard для обхода предварительного owned-copy; никаких unknown→GenerationResult assertions.

**Фактический вход ядра.** Публичный `createGenerationSearch(raw, {now, isCancelled?, deadlineMs?})` возвращает cursor с `next()`: события yield/candidate/finished. `generate` синхронно исчерпывает тот же cursor и не должен вызываться блокирующим циклом в host. Raw остаётся прежним `{hall, mode, budget}`; normal/extended имеют внутренние сроки 10000/30000 мс и прежний общий ledger. Часы/функции/opaque handles/DOM/ProjectCommand не пересылаются. Из raw нельзя извлекать witness-план вместо обычного поиска. Формулы/геометрические валидаторы/эталоны/seed/рабочие бюджеты не меняются. Единственное согласованное владельцем дополнение ядра U01.4 — optional deadlineMs в области его внедрённых монотонных часов: раньше прежнего срока остановиться можно, позже нельзя; без поля прежние normal/extended сохраняются. Неправильный control даёт явный internalError, истёкший срок — прежний доменный timeout либо выбранный terminal success с уже проверенным кандидатом.

**Конверт и идентичность.** Все сообщения содержат protocolVersion, type и непрозрачный requestId; сообщения операции также contextId, inputRevision и baseRevision. Числовые ревизии — неотрицательные safe integers; строки идентификаторов — непустые, до128 UTF-16 code units. RequestId не переиспользуется в течение жизни client, ответ дополнительно связан с конкретным экземпляром Worker. contextId определяет рабочий контекст, inputRevision — любую правку геометрического ввода, baseRevision — ревизию принятого основания. Это runtime-токены host, не новые поля канона и не присвоение готовности Project. Смена контекста инвалидирует операцию даже при совпавших числах ревизий; ценовые изменения сами по себе геометрический ввод не меняют. E позже уточнит адаптер этих токенов к своей оболочке.

Команды host: start с detached raw и cancel для конкретной операции. Браузерный client сам добавляет в start конечный deadlineEpochMs = performance.timeOrigin + startedAt +10000/30000; caller не вправе подставлять этот wire-реквизит. Codec версии -2 допускает untimed start только для изолированных in-process bindings/тестов; настоящий entry требует deadline и свой timeOrigin. Полная identity и схема cancel/ответов не меняются. Ответы Worker: progress без геометрии, finished с неизменённым terminal GenerationResult, failed с ограниченной категорией transport/runtime-ошибки. Для start и ответов операции требуется полное совпадение идентичности. Неизвестная версия/type, лишние поля, повторный start того же ID, malformed/non-cloneable ввод и просроченный ответ не получают частичный успех. Ошибки конверта и postMessage не маскируются под доменный invalidInput; raw неправильного профиля после допустимого конверта проверяет прежнее ядро. Точную TypeScript/runtime-схему и лимиты обхода данных реализовать в U01.2 до adapter; лимиты поиска при этом не расширять.

**Lifecycle host.** Один активный поиск и один живой Worker на client; без очереди и пула. Состояния idle → running → success/failure/cancelled/timeout, затем возможен новый запрос; dispose окончателен и освобождает Worker/listeners/timers. Успех — только результат для текущих requestId/context/revisions/Worker-instance до внешнего срока. Новый start сначала инвалидирует прежнюю операцию; поздний cancel(A) не отменяет B. При геометрическом редактировании, смене документа, cancel, dispose, error/messageerror или ошибке отправки принятый план остаётся прежним. Каждая операция разрешается ровно один раз; повторные terminal-сообщения ничего не применяют. Finished передаётся вызывающему коду как результат поиска, а не автоматически записывается в Project/сохранения.

**Отмена и время.** Host помечает операцию недействующей сразу при cancel/смене ввода, не ждёт ответа Worker и не принимает даже уже поставленный в очередь success. Можно послать cooperative cancel; Worker, переставший обслуживать сообщения, завершается через terminate. У простейшего первого адаптера cancel может сразу завершать Worker; новый запрос использует новый экземпляр. Синтетический host cancelled/timeout/workerError не выдаётся за terminal GenerationResult с выдуманными счётчиками ядра. Последний progress остаётся лишь неполной диагностикой.

Host измеряет elapsed от start монотонными часами и отсеивает ответы при elapsed >=10000/30000 мс по mode, включая доставку и запуск Worker. Watchdog завершает зависший Worker; при задержке таймера в фоновой вкладке проверка часов на каждом сообщении всё равно запрещает поздний success. Worker создаёт собственный монотонный control. По выбору владельца в U01.4 используется единый срок с резервом250мс внутри него на clone/доставку/host decode: deadlineMs = deadlineEpochMs − worker.performance.timeOrigin −250. Холодный запуск и очередь входят в общий срок, никакого перезапуска отсчёта при первом pump. Локальные performance.now разных потоков напрямую не сравниваются, они переводятся через timeOrigin. Ядро берёт более раннюю границу; время/узлы/кандидаты не увеличиваются. Резерв250мс — начальная проверяемая величина доставки на этом ПК, не обещание SLA: при долгом неделимом next/задержке платформы host всё равно отбрасывает поздний ответ. И отмена, и срок проверяются до принятия результата; результат не принимается после смены основания, даже если геометрически допустим.

**Порции и транспорт.** Между конечными порциями next() Worker возвращает управление task queue: одних Promise/microtask недостаточно для обработки cancel. Число next на порцию и временной квант фиксируются до U01.3 по измерению существующего cursor; одиночный синхронный next может превысить квант, это не обещание мгновенного прерывания. Host terminate — аварийная граница без изменения алгоритма. Candidate-события остаются внутри Worker; наружу публикуется лишь terminal результат, progress содержит ограниченные счётчики/фазу без процентов готовности и без копирования всех промежуточных планов. SharedArrayBuffer, новые серверные заголовки и зависимости не требуются этим контрактом.

Используется structured clone, не JSON.stringify всего результата: q/площади/числа/BigInt, если они встречаются, не преобразуются с потерей точности. После клонирования frozen/ownership-признаки ядра не считаются перенесёнными. Клиент проверяет конверт и допустимую структуру данных и выдаёт собственную detached immutable копию; шаблон unknown не приводится к GenerationResult без проверки. Статусы Building/Project pending и optimalityProven=false сохраняются. Это доверенный локальный код Worker, не импорт произвольного сетевого сертификата и не новая проверка полного Project; freshness относительно source/revision контролирует host.

Последующее редактирование не перезахватывает origin: prepareFootprintRevision сравнивает текущие5полей с первоначальным снимком, технология/высота сравниваются с их исходными transient значениями. Валидная правка обновляет lastValid и diff; невалидная сохраняет прошлый lastValid, но помечает текущий ввод ошибочным и блокирует «Далее». Нельзя продолжить по устаревшему lastValid, пока видимый текст ошибочен. Смена источника — отдельное явное действие, новое baseline только после полной проверки. Возврат к исходным значениям очищает соответствующий diff.

Любая геометрическая правка (включая невалидную высоту/технологию и начало смены контекста) вызывает внешний onGeometryEdit до ожидания валидации; будущий владелец U05 свяжет его с client.invalidate. В U02 Worker не создаётся и поиск не запускается. Принятый план/исходная смета от редактирования не перезаписываются. Движение назад/вперёд использует то же контролируемое состояние родителя, не повторную инициализацию компонента. «Далее» передаёт только актуальный целиком валидный ввод; не добавляет комнаты или площади за пользователя.

### U06.1 — Поведение камеры и результаты независимой приёмки

Камера принадлежит отображению конкретной сцены. Обычный ререндер/прогресс/текст не сбрасывают её; resize сохраняет камеру, но прерывает текущий жест.
