# Работа с репозиторием ОСНОВА

Этот документ описывает действующее приложение и порядок его проверки. Продуктовые требования находятся в [спецификации](PROJECT_SPEC.md), приоритеты — в [дорожной карте](../ROADMAP.md), обязательные правила для Codex — в [AGENTS.md](../AGENTS.md).

## Рабочая папка и инструменты

Работать нужно в корне Git-репозитория, где находятся `.git`, `package.json`, `src/` и `docs/`. Родительская папка с несколькими копиями проекта корнем репозитория не является. Перед изменениями проверить `git status --short --branch`; не затирать существующие правки. Нужны Node.js 24 и npm. Зависимости устанавливаются из зафиксированного `package-lock.json` командой `npm ci`.

## Карта приложения

- `src/pages/` — главная, карточка дома и сравнение; маршруты также включают подбор и демо-кабинет.
- `src/features/projects/` — каталог, фильтры и избранное.
- `src/features/estimate/` — демонстрационная модель стоимости и срока, калькулятор, снимки расчётов и PDF.
- `src/features/finder/` — подбор дома; `src/features/account/` — локальный демо-кабинет.
- `src/features/backend/` и `src/features/demoChat/` — публичный доступ к ограниченным демо-функциям Supabase. Границы данных и история ручного применения SQL описаны в [отдельном документе](SUPABASE_APPLICATIONS.md).
- `supabase/migrations/` — SQL-схемы; `supabase/tests/` — проверки ограничений и прав.
- `e2e/` — браузерные сценарии Playwright; `src/**/*.test.ts` — модульные тесты.

Избранное и сохранённые расчёты находятся в `localStorage`; демо-сессия и черновик калькулятора — в `sessionStorage`. Между устройствами они не синхронизируются. Фотографии каталога и шрифт PDF хранятся локально; интерфейс загружает DM Sans из Google Fonts. Опубликованные проекты, цены и сроки демонстрационные.

## Локальная проверка

После `npm ci` запустить `npm run dev` для локального просмотра. Перед отправкой изменений выполнить затронутые проверки, а для обычного полного цикла:

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
npm run build
git diff --check
```

При изменении пользовательских сценариев обязательны соответствующие браузерные тесты. Исторические отчёты в `docs/archive/` и датированный аудит фиксируют состояние на момент их создания; актуальное состояние определяют код, действующие документы и свежий результат проверок.

## Публикация

Ветка `main` отправляется в `origin` на GitHub. Workflow `ci.yml` проверяет типы, линтер, форматирование, модульные и браузерные тесты и сборку. Workflow `deploy.yml` после push в `main` собирает сайт и публикует `dist` на GitHub Pages; `404.html` поддерживает прямые ссылки на внутренние страницы. Базовый адрес production-сборки — `/osnova/`.

После завершённой правки проверить diff, коммитить и отправить изменения согласно `AGENTS.md`, затем проверить CI и публикацию. Ошибки проверок или публикации явно указывать в отчёте. Разрушительные Git-операции не применять.

## Обновление документации

При изменении поведения синхронно обновлять спецификацию и README. При изменении ставок, формул, коэффициентов или сроков обновлять версию демо-модели в коде и [исследование цен](PRICING_RESEARCH.md); при изменении передаваемых данных и SQL — [описание Supabase](SUPABASE_APPLICATIONS.md). Источники иллюстраций хранить в [реестре](IMAGE_SOURCES.md). До согласования полного комплекта документации проекта функциональный код не разрабатывать.
