# Заявки через Supabase: подготовка к запуску

ОСНОВА — портфолио-проект. Владелец выбрал приём реальных обращений с уведомлением на `vanya_silorov@mail.ru`. Эта задача касается связи с автором портфолио, а не обещания строительства вымышленной компанией.

## Что подготовлено

Миграция `supabase/migrations/20261013210000_contact_requests.sql` описывает закрытую таблицу заявок. В ней предусмотрены имя, email, сообщение, номера выбранных проектов, текстовая сводка расчёта, версия и время согласия, статус обработки и статус email-уведомления. `client_request_id` нужен для защиты от дублей при повторной отправке. Контактные данные не должны появляться в URL, браузерных логах или публичных таблицах.

Для таблицы включён Row Level Security. У ролей `anon` и `authenticated` отозваны права; публичных политик чтения и записи нет. Будущая серверная функция должна проверять данные и защиту от спама, записывать заявку своим секретным ключом и отправлять уведомление. Секретный ключ нельзя передавать в Vite/React или GitHub Pages. Ошибка email не должна терять уже записанную заявку: `notification_status` позволит увидеть сбой и повторить уведомление. Само сохранение заявки и отправка email **ещё не реализованы**.

После применения миграции на тестовой среде нужно выполнить `supabase/tests/contact_requests_security.sql`: он проверяет RLS и отсутствие прав чтения/записи у браузерных ролей. Эта проверка пока не запускалась, поскольку локальный Supabase и российский сервер ещё не настроены.

## Проверка перед включением формы

1. **Размещение данных.** На 13.10.2026 в панели проект `ykmuwefaohpkmfdjxjkx` расположен в `West EU (Ireland)`. Сайт ориентирован на пользователей в России. Перед сбором персональных данных граждан РФ нужно проверить применимость требований [152-ФЗ, статья 18, часть 5](https://mintrud.gov.ru/docs/laws/130) к выбранной схеме хранения с профильным специалистом. [Supabase указывает](https://supabase.com/docs/guides/platform/regions), что регион определяет расположение основных данных; в списке управляемых регионов нет России. Владелец выбрал [самостоятельный запуск Supabase на российском сервере](https://supabase.com/docs/guides/self-hosting) для будущих реальных заявок. По [официальным системным требованиям](https://supabase.com/docs/guides/self-hosting/docker) минимальная конфигурация полного стека — 2 CPU, 4 ГБ RAM и 40 ГБ SSD; рекомендуемая — 4 CPU, 8 ГБ RAM и 80 ГБ SSD. Потребуются администрирование, обновления, резервные копии и защита сервера. Хостинг ещё не выбран, а форма на сайте не включена.
2. **Владелец данных и документы.** Указать фактического оператора персональных данных, контакт для запросов, цель обработки, срок хранения и порядок удаления. Подготовить текст политики и отдельное согласие для формы. Версия согласия должна совпадать с `consent_version` в записи.
3. **Уведомления.** Для отправки на `vanya_silorov@mail.ru` нужен подтверждённый адрес отправителя и почтовый сервис, например схема Edge Function + Resend из [документации Supabase](https://supabase.com/docs/guides/functions/examples/send-emails). Ключ сервиса хранится только в секретах серверной функции.
4. **Защита формы.** Проверка полей на сервере, ограничение размера тела, защита от автоматических отправок, контроль ошибок и тест отправки без реальных данных. [Supabase описывает Turnstile](https://supabase.com/docs/guides/functions/examples/cloudflare-turnstile) как один из вариантов защиты.
5. **Публикация схемы.** В панели управляемого проекта раздел Integrations сейчас показывает `No connections yet` и предложение подключить GitHub. Наличие GitHub-репозитория сайта само по себе не означает автоматическую доставку миграций. Миграцию следует применять только к будущей российской среде после проверки пустой схемы и теста прав доступа; текущая база в Ирландии остаётся без изменений. Для самостоятельного размещения миграции и функции потребуется отдельный процесс развёртывания, который будет описан после выбора хостинга.

## Порядок реализации

После решения вопросов размещения данных и согласия: серверная функция приёма → email-уведомление и повтор при сбое → форма с явным согласием → проверка доставки и прав доступа на тестовых данных → включение на сайте. Личный кабинет и чат проектируются отдельно; они также могут содержать персональные данные.
