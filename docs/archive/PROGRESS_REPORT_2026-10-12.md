## Что нужно подкорректировать

1. **Проверить последнюю версию целиком.** Старый аудит подтвердил 29 модульных и 6 браузерных сценариев до последующих изменений. После добавления новых параметров калькулятора, сроков и пояснений нужна свежая проверка основных сценариев, узких экранов и команд `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`; при готовой браузерной среде — `npm run test:e2e`. До такой проверки нельзя переносить прежние результаты на текущую рабочую копию.
2. **Сделать путь после расчёта понятным.** Сейчас пользователь может получить ориентир, но не может отправить его менеджеру. В шапке есть только честное информационное окно «Личный кабинет — скоро», а в подвале нет действующих контактов. Следующий продуктовый шаг — определить реальный канал обращения и связать его с текущим расчётом. Форма не должна показывать успешную отправку без работающей доставки заявки.
3. **Уточнить формулировки концепций.** Преимущества в сравнении полезны для выбора, но отдельные характеристики террас, остекления и планировок пока не подтверждены чертежами. Перед публикацией как реальных предложений потребуются планы, состав комплектации и проверка описаний.
4. **Оценить удобство длинного калькулятора на телефоне.** Детализация стала содержательнее; после проверки в браузере стоит решить, помогают ли порядок полей, раскрытие этапов и итоговый блок быстро получить ответ без лишней прокрутки. Это задача на удобство, а не подтверждённая ошибка расчёта.
5. **Держать документацию актуальной.** Предыдущий аудит остаётся историей исправлений: он перечисляет как отсутствующие регион, доставку и сроки, которые позже появились в демо. Текущее состояние следует брать из этого отчёта, `README.md` и кода.
